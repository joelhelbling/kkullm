# Kkullm Roadmap — 2026-06-12

A speedrun triage of known issues across the web UI, CLI, and data model,
stitched into a dependency-ordered plan. Each item below is a GitHub issue;
this document is the map and the rationale.

## Decisions made during triage

- **Cross-project visibility → an "All" selector option.** Rather than a magic
  "orchestration" project, the project selector gets an explicit **All** entry
  that aggregates every project's cards. "orchestration" is demoted to a normal
  project. (#30)
- **`blocked` becomes an orthogonal flag, not a status.** This is the biggest
  shift. Today `blocked` is a lifecycle *status*, so blocking a card destroys
  its column. Instead, `blocked` becomes a boolean flag a card carries *while*
  sitting in its real column (`considering → todo → in_flight → completed`, plus
  `tabled`). Consequences:
  - The board's **blocked column disappears**; blocked cards render in-place
    with a badge.
  - **Unblocking is just clearing the flag** — no "restore previous status"
    machinery needed (this dissolved the original trickiest feature).
  - **Blocking keeps the assignee.**
  - The orchestrator gets a dedicated **blocked view** (filtered board) for
    triage.
  - In the web UI, editing a blocked card's status/assignee prompts
    *"Unblock this card?"*.
- **Block reason rides on a tagged comment.** `--reason "..."` posts a specially
  *kinded* comment (`block`/`unblock`) rather than adding a card column, keeping
  the "why" in the card's timeline with who/when for free. This needs one small
  new primitive: a **kind/tag on comments**. (#31)
- **CLI block/unblock = flags on `update`, not new verbs.** `card update
  --blocked/--unblocked` preserves the agent-facing contract in the
  `/kkullm:cli` skill: *"verbs are consistent — list/get/create/update only;
  no show, no add."* A `card block` verb would break that promise. (#31)
- **Force-move is for anyone, rules stay as the default.** Transition rules
  remain the guardrail; an explicit override (`--force` on the CLI, Alt-drop in
  the web UI) bypasses them and is recorded as *forced*. (#35)
- **Audit trail: status + assignment first, schema designed to expand.** An
  append-only event log with actor + timestamp. It is no longer a prerequisite
  for unblocking (see above), so it moved later — but it remains the thing that
  gives `--as`/`KKULLM_AGENT` somewhere to land and that enables
  "formerly-assigned" scoping. (#36, #37)
- **No web auth — by design, for now.** Kkullm is self-hosted with a single
  human operator who is the web UI's only user. So *admin == the operator*, and
  the existing `RequireAdmin` chokepoint (`web/admin_middleware.go`, a
  pass-through today) is where enforcement would land **if** auth is ever
  needed. If we add it later, the priority is keeping bootstrapping/onboarding
  friction minimal. Until then, operator-gated features (the All view, the
  orchestrator blocked view) are functionally open.

## The dependency spine

```
Phase 2 core: blocked-as-flag (#31)
   ├─> #32  web: in-place badge + unblock-on-edit confirm
   ├─> #33  web: orchestrator blocked view
   └─> #34  agent view: scope blocked cards to the agent
                                    │ ("formerly assigned" part)
                                    ▼
Phase 4: audit trail (#36) ──> #37  actor identity recorded
                            └─> #34  enables "formerly assigned"
                            └─> #35  records "forced" moves
```

`#31` (blocked-as-flag) is the keystone for all the blocked work. `#36` (audit
trail) is a secondary keystone for attribution and history, but is no longer on
the critical path to unblocking.

## Notes for whoever picks this up

- `blocked` appears in `model/model.go` in three places (`ValidStatuses`,
  `AllStatuses`, `ValidTransitions`) plus the store, API, web templates, and the
  CLI — #31 is a wide change; budget for it.
- The CLI skill (`plugins/kkullm/skills/cli/SKILL.md`) is currently accurate and
  good; #38 keeps it that way.
- The original "resolve a blocked card → restore previous column/assignee" idea
  was deliberately dropped: with `blocked` orthogonal, the column was never lost,
  so there is nothing to restore.
